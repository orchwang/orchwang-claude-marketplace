# Reference: 데이터 품질 · 거버넌스 · DataOps

신뢰할 수 있는 데이터 시스템을 완성하는 저류(undercurrents)의 실무. 설계·리뷰 시 "이건 챙겼나"를 확인하는 체크리스트로 쓴다.

## 1. 데이터 품질 차원

측정 가능한 축으로 품질을 정의한다.

| 차원 | 질문 | 점검 방법 |
|------|------|----------|
| 정확성 Accuracy | 실제와 일치하는가 | 원천 대조·샘플 검증 |
| 완전성 Completeness | 빠진 값·행이 있는가 | null 비율·행수 대조 |
| 일관성 Consistency | 시스템 간 값이 맞는가 | 크로스 소스 대사(reconciliation) |
| 적시성 Timeliness | 신선한가 | freshness(마지막 적재 시각) |
| 유일성 Uniqueness | 중복이 없는가 | PK 유일성·dedup |
| 유효성 Validity | 규칙/도메인에 맞는가 | 범위·enum·형식 검증 |

## 2. 테스트 & 데이터 계약

- **테스트 유형**: 스키마 테스트(not_null·unique·relationships·accepted_values), 비즈니스 규칙 테스트, 볼륨/이상 탐지, freshness.
- **위치**: 수집 직후(원천 계약 위반 조기 감지)와 변환 후(마트 정확성) 양쪽.
- **데이터 계약(Data Contract)**: 생산자–소비자 간 스키마·의미·SLA·호환성 정책을 명시. 스키마 레지스트리(Kafka)·dbt source·계약 도구로 강제.
- **실패 정책**: 차단(block) vs 경고(warn)를 데이터 중요도로 구분. 조용한 실패 금지.

## 3. 관측가능성 (Observability)

파이프라인이 "돌긴 도는데 데이터가 틀린" 상태를 잡는다. 5축:
- **Freshness**: 기대 시각에 도착했나.
- **Volume**: 행수가 정상 범위인가(급감/급증).
- **Schema**: 스키마가 예고 없이 바뀌었나.
- **Distribution**: 값 분포·null률이 정상인가.
- **Lineage**: 어디서 와서 어디로 가는가(영향 범위 파악).

> 알람은 **행동 가능(actionable)**해야 한다. 소음 알람은 신뢰를 무너뜨린다. SLO/threshold를 데이터로 정한다.

## 4. 거버넌스 & 데이터 관리

- **카탈로그 & 리니지**: 데이터 자산·소유자·정의·의존성 추적.
- **접근 제어**: 최소 권한, 컬럼/행 수준 보안, PII 마스킹·토큰화.
- **분류 & 컴플라이언스**: PII/민감도 태깅, 보존·삭제 정책(GDPR 등).
- **마스터/참조 데이터**: 단일 진실 원천(SSOT) 관리.
- **비용 거버넌스**: 스토리지·컴퓨트 비용 가시화, 파티션 프루닝·수명주기 정책.

## 5. DataOps · 운영 · 신뢰성

- **CI/CD**: 변경분만 빌드/테스트(dbt slim CI), 환경 분리(dev/stg/prod), 배포 자동화.
- **오케스트레이션 신뢰성**: 재시도·타임아웃·알림·SLA miss 감지, **멱등성**과 **백필(backfill)** 경로 상시 확보.
- **인시던트 대응**: 감지→분류→완화→사후분석. 런북·온콜.
- **신뢰성 지표**: 데이터 SLA/SLO(freshness·완전성), 인시던트 MTTR, 파이프라인 성공률.
- **버전·재현성**: 코드·설정·(가능하면) 데이터 스냅샷(Iceberg 타임트래블)으로 재현 가능한 파이프라인.

## 6. 멱등성 & 재처리 — 반드시 설계에 넣을 것

- **멱등(idempotent) 쓰기**: 같은 입력·구간을 재실행해도 결과 불변(MERGE/upsert, 파티션 덮어쓰기, `unique_key`).
- **재처리 가능성**: 원본(Bronze) 보존 → 언제든 하위 계층 재생성. 로그 리플레이(Kappa)·타임트래블(Iceberg).
- **백필 전략**: 과거 구간을 논리적 data interval 기준으로 안전하게 다시 채움(대량 폭주 방지, `catchup` 통제).
- **지연 도착(late-arriving) 데이터**: 워터마크(스트림)·증분 윈도우 재계산(배치)으로 처리.

## 7. 설계 리뷰 체크리스트 (요약)

- [ ] 각 요구가 수명주기 어느 칸에 속하는지 명확한가
- [ ] 신선도·일관성·규모 요구가 수치로 정의됐는가
- [ ] 아키텍처 패턴 선택 근거(트레이드오프)가 있는가
- [ ] 모든 변환이 멱등하고 백필 경로가 있는가
- [ ] 원천 계약·핵심 마트에 테스트가 걸렸는가
- [ ] freshness/volume/schema/distribution 관측이 있는가
- [ ] PII·접근제어·보존 정책이 반영됐는가
- [ ] 실패 시 감지·알림·복구 절차가 있는가
- [ ] 스토리지/컴퓨트 비용이 통제되는가(파티셔닝·파일크기·수명주기)
