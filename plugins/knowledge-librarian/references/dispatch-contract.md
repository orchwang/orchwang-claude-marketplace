# Dispatch Contract Reference

`knowledge-librarian`이 관련 지식을 모아 다른 전문 서브에이전트에게 근거로 전달(dispatch)하는 계약. 본 플러그인의 핵심 차별점(indexer → specialist)이다.

## 페이로드 구조

librarian이 대상 서브에이전트에게 전달하는 논리적 페이로드:

```
{
  question:     "<사용자 질문>",
  evidence: [
    {
      source:   "<소스 name>",
      path:     "<소스 루트 기준 상대경로>",
      title:    "<문서 제목>",
      excerpt:  "<관련 섹션 발췌>"
    },
    ...
  ],
  instructions: "아래 evidence를 우선 근거로 답하라. 부족하면 추가 탐색을 요청하라. 인용 시 [source] path를 명시하라."
}
```

실제 전달은 Agent 도구 프롬프트에 위 내용을 마크다운으로 직렬화하여 넣는다.

## 대상 에이전트 검증

- `--to`로 지정된 에이전트는 **마켓플레이스에 실재하는 에이전트**여야 한다.
- 권장 후보: `data-engineer`, `ontology-expert`, `general-purpose`. (마켓플레이스 구성에 따라 확장 가능)
- 미존재 에이전트 지정 시: "에이전트 '{name}'을 찾을 수 없습니다. 사용 가능한 에이전트: ..." 안내 후 중단.
- `--to` 미지정 시: `AskUserQuestion`으로 질문 성격에 맞는 후보를 제시한다. **무음 기본값을 적용하지 않는다.**

## 발췌 상한 (Open Q4 결정)

- 상위 문서 **최대 5개**를 근거로 사용한다.
- 문서당 발췌는 **최대 ~1500자**로 제한한다.
- 초과 시 질문과 관련된 heading 섹션을 우선 남기고 나머지를 절삭한다.
- 발췌가 전체 상한을 넘으면 상위 랭킹 문서부터 채우고 하위는 제목·경로만 참고로 첨부한다.

## 출처 라벨링

- 모든 발췌에 `[{source}] {path}` 형태의 출처 라벨을 부착한다.
- 대상 에이전트가 답변에서 근거를 인용할 수 있도록 한다.
- librarian은 디스패치 후 사용한 출처 목록을 사용자에게 함께 보고한다.

## 디스패치 흐름 요약

1. `knowledge-search` 랭킹으로 상위 문서 선별 (기본 3~5)
2. 선별 문서를 소스에서 READ → 질문 관련 섹션 발췌 (상한 적용)
3. 대상 에이전트 결정 (지정 또는 AskUserQuestion)
4. Agent 도구로 대상 서브에이전트 호출 — 위 페이로드 전달
5. 대상 에이전트 응답 + 사용한 출처 목록 보고
