# Reference: 형식 기반 · 시맨틱 레이어 · 비교 · 거버넌스

객체·링크·매핑·액션(→ 다른 references)을 떠받치는 이론 기반과, 인접 개념과의 경계, 그리고 운영 거버넌스.

## 1. 지식 그래프 · 형식 기반

온톨로지의 학문적 뿌리와 두 갈래 형식 모델.

### 1.1 RDF / OWL (시맨틱 웹 계열)
- **RDF**: 세계를 **(주어, 술어, 목적어) 트리플**로 표현. URI로 전역 식별.
- **OWL**: 클래스·프로퍼티·공리로 **추론(inference)** 가능한 형식 온톨로지. 표현력·논리 추론이 강점.
- **SPARQL**: 트리플 그래프 질의.
- **성격**: 표준·상호운용·추론 중심. 무겁고 학습곡선이 있음.

### 1.2 속성 그래프 (Property Graph)
- **노드·엣지에 속성**을 직접 부착(예: Neo4j, TigerGraph). Cypher/Gremlin으로 질의.
- **성격**: 실용·탐색 친화·운영 시스템에 가까움. 팔란티어식 "객체·링크" 온톨로지의 정신적 모델과 잘 맞음.

### 1.3 어느 쪽인가
- **추론·표준 상호운용**이 핵심이면 RDF/OWL.
- **운영 애플리케이션·탐색·액션**이 핵심이면 속성 그래프 스타일(객체·링크).
- 실무 온톨로지(FDE 관점)는 대개 후자에 가깝고, 필요 시 시맨틱 표준과 교환.

## 2. 시맨틱 레이어 vs 데이터 모델

- **데이터 모델(물리/논리)**: 저장·정규화·성능 중심. 테이블·컬럼·키·인덱스.
- **시맨틱 레이어(온톨로지)**: **의미·비즈니스 언어** 중심. 객체·링크·지표. 여러 물리 모델 위에 하나의 일관된 의미.
- **관계**: 온톨로지는 데이터 모델을 대체하지 않고 **그 위에** 놓여 매핑으로 연결된다. 물리 파이프라인/저장/처리는 `data-engineer` 플러그인 소관.

## 3. 온톨로지 vs 도메인 주도 설계(DDD)

같은 뿌리(도메인 언어·모델), 다른 층.

| 축 | DDD | 온톨로지(시맨틱 레이어) |
|----|-----|------------------------|
| 목적 | **행위/트랜잭션** 소프트웨어 설계 | **의미/분석·운영**을 위한 통합 모델 |
| 1급 개념 | Entity·Value Object·Aggregate·Bounded Context | 객체 타입·링크 타입·액션 |
| 경계 | Bounded Context로 **분할** | 조직 횡단 **통합** 그래프 |
| 관계 | Aggregate 내부/참조 | 링크가 1급, 자유로운 그래프 탐색 |
| 일관성 | Aggregate = 트랜잭션 경계 | 액션·write-back이 트랜잭션 경계 |
| 언어 | Ubiquitous Language(컨텍스트별) | 조직 공통 의미(엔티티 해소로 통합) |

- **공통**: 도메인 전문가의 언어에서 출발, 의미를 코드/모델의 1급 시민으로.
- **차이**: DDD는 한 서비스의 행위를 **경계 지어** 설계, 온톨로지는 여러 소스를 **가로질러 통합**해 분석·의사결정·액션을 지원.
- **함께 쓰기**: DDD Aggregate/도메인 이벤트가 온톨로지 객체·액션의 좋은 원천이 된다. 상충이 아니라 층이 다르다.

## 4. 거버넌스 · 진화 · FDE 워크플로

온톨로지는 살아있는 자산이라 운영·진화 규율이 필요하다.

- **버전 관리**: 객체/링크/액션 스키마 변경의 버전·호환성(속성 추가는 안전, 삭제·의미변경은 신중).
- **권한·소유권**: 객체·속성·액션 단위 접근 제어, 도메인별 소유자(steward).
- **도메인 협업(FDE 워크플로)**: Forward Deployed Engineer가 현장 도메인 전문가와 함께 — 결정/액션에서 출발 → 객체·링크 도출 → 소스 매핑·엔티티 해소 → 액션 → 반복. 모델을 도메인과 **공동 소유**.
- **품질·리니지**: 백킹 데이터셋 → 속성 변환 → 객체까지의 계보를 추적, 신선도·정확성 모니터링.
- **진화 관리**: 사용 로그·피드백으로 미사용 객체 정리, 새 결정 요구에 맞춰 확장.

## 5. 경계 요약

- **물리 파이프라인·저장·처리·수집** → `data-engineer` 플러그인.
- **의미 계층·객체·링크·매핑·액션·거버넌스** → 이 플러그인(`ontology-expert`).
- 두 층은 **매핑**과 **신선도(백킹 데이터셋 갱신)**로 맞물린다.
