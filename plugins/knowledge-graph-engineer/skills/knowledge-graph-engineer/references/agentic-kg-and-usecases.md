# Agentic KG & Use Cases — 에이전트가 도구·기억으로 쓰는 지식 그래프

> `knowledge-graph-engineer` 플러그인 핵심 참조 문서. 그래프를 **도구(tool)**이자 **기억(memory)**으로 삼는 에이전트 설계, end-to-end 구축 파이프라인, 도메인 변주, 프로덕션 체크리스트, 커리큘럼 8단계 지도를 한 곳에 정리한다.
>
> 한 문장 요약: **아키텍처는 하나, 변주는 도메인마다 — 코퍼스 → LLM 추출 → 그래프 DB → GraphRAG·추론 → 에이전트 write-back.**
>
> 출처: `orchwang.github.io` 위키 Agentic-Knowledge-Graph 시리즈 7·8단계 및 커리큘럼.

## 0. 좌표 — Agentic KG란 무엇인가

Agentic KG는 그래프의 *주체*를 사람이 짠 파이프라인에서 **에이전트**로 바꾼다. 읽기 전용이던 그래프가 *읽고 쓰는* 살아있는 기억이 된다. 두 방향이 핵심이다.

- **도구(읽기)**: 에이전트가 자연어를 Cypher/SPARQL로 번역(text-to-Cypher)하고 질의를 스스로 계획해 탐색한다.
- **기억(쓰기)**: 대화·관찰에서 얻은 새 사실을 그래프에 **write-back**해, 시간과 함께 자라는 **시간적 지식 그래프(temporal KG)**를 만든다.

```
              ┌──────────── 검색–추론–행동 루프 ────────────┐
사용자/환경 → 에이전트 ─① 도구: NL→Cypher·탐색→ 그래프 읽기
                 ▲              │
                 │              ▼
            (다음 턴 문맥)   추론·답 생성
                 │              │
              시간적 KG ◀─② 기억: write-back(새 사실·유효기간)◀┘
```

**핵심 명제**: 그래프는 루프 바깥의 정적 DB가 아니라, 루프 안에서 읽히고 쓰이며 자라는 살아있는 기억이다. 이 되먹임이 Agentic KG를 이전 단계와 가른다.

## 1. 그래프를 도구로 — 에이전트가 스스로 질의한다

### 1.1 핵심 개념

- **text-to-Cypher**: 스키마를 시스템 프롬프트에 싣고, 질문을 그래프 질의로 번역해 실행 → 결과를 자연어로 답한다.
- **질의 계획(query planning)**: 한 번에 못 푸는 질문을 여러 단계로 분해하고, 중간 결과를 보며 다음 질의를 재계획한다(개체 찾기 → 이웃 탐색 → 조건 필터).
- **다중 도구 오케스트레이션**: 그래프 질의 하나만 쓰지 않는다. GraphRAG local/global, 벡터 검색, 링크 예측을 각각 도구로 쥐고 질문에 맞춰 고른다.

### 1.2 의사결정 규칙 — 어떤 도구를 쓸까

| 질문 유형 | 선택 도구 | 근거 |
| --- | --- | --- |
| 특정 사실 조회 | 그래프 질의 (text-to-Cypher) | 정확한 경로·정답 필요 |
| 코퍼스 전체 요약·주제 | GraphRAG global search | 커뮤니티 요약 종합 |
| 개체 근방·국소 문맥 | GraphRAG local search | 이웃 서브그래프 |
| "비슷한 것" | 벡터 검색 | 의미 유사도 |
| 빠진 관계 추정·예측 | 링크 예측(6단계) | 아직 없는 엣지 |

### 1.3 코드 스니펫

```python
# 그래프 질의를 에이전트 도구로 등록 (개념)
def graph_query(cypher: str) -> list[dict]:
    """스키마에 맞는 Cypher를 실행해 결과를 반환한다."""
    return neo4j.run(cypher)

# Q: "미리내 팀과 3다리 안에 연결되고 ML을 하는 사람은?"
#  step1  MATCH (t:Team {name:'미리내'})              # 개체 찾기
#  step2  MATCH (t)-[*1..3]-(p:Person)                # 이웃 탐색(다중 홉)
#  step3  WHERE p.skill='ML' RETURN p                 # 조건 필터 → 답
#  ↑ 각 단계의 중간 결과를 보고 다음 질의를 재계획하는 것이 query planning
```

### 1.4 함정·체크리스트

- [ ] 생성된 Cypher가 스키마를 오해하지 않는가 → **스키마 검증** 게이트.
- [ ] 파괴적 질의 방지 — write/delete 질의는 실행 전 확인.
- [ ] 답에 **근거 경로(evidence path)**를 함께 반환(설명가능성, 1단계 원칙).
- [ ] 질의 깊이·홉 수 상한을 둬 폭주 방지.

## 2. 그래프를 기억으로 — write-back과 temporal KG

### 2.1 핵심 개념

- **write-back**: 에이전트가 대화·관찰에서 확인한 새 사실을 그래프에 써 넣는다 → 그래프가 에이전트의 **장기 기억**이 된다.
- **왜 벡터 메모리가 아닌 그래프인가**: 벡터 메모리는 흩어진 사실을 *연결*하지 못한다. "이 사용자에 대해 아는 것을 종합해줘" 같은 질문에 약하다. 그래프 메모리는 사용자·선호·사건을 하나의 연결된 기억으로 키운다.
- **시간적 지식 그래프(temporal KG)**: 사실(엣지)마다 유효 기간을 붙여 시간을 다룬다.

### 2.2 시간 모델과 무효화 규칙

| 개념 | 의미 |
| --- | --- |
| **유효 시간(valid time)** | 이 사실이 *현실에서* 언제부터~언제까지 참인가 |
| **기록 시간(transaction time)** | 그래프가 이 사실을 *언제* 알게 됐는가 |
| **bi-temporal** | 위 둘을 함께 관리 |
| **무효화(invalidation)** | 새 사실이 옛 사실과 모순되면 **지우지 않고** 옛 사실을 `valid_to`로 닫고 새 사실을 연다 |

**규칙**: 사실은 덮어쓰지 않는다. 닫고 새로 연다. → 과거가 보존되어 "*그때* 김지수는 어느 팀?" 같은 시간 관통 질의에 답할 수 있다.

```text
# 사실이 시간에 걸쳐 무효화·갱신되는 모습 (개념)
(김지수)-[:소속 {valid_from:2024-01, valid_to:2025-06}]->(A팀)   # 닫힘(무효화)
(김지수)-[:소속 {valid_from:2025-06, valid_to:null    }]->(B팀)   # 현재 유효(열림)
```

실무 프레임워크: **Graphiti**(Zep의 오픈소스 엔진)는 대화·이벤트에서 사실을 추출해 bi-temporal 그래프로 쌓고, 모순 사실을 무효화하며 시간 관통 질의에 답한다. 사실을 지우지 않고 *축적*하므로 "언제부터 이 선호가 바뀌었지?"에도 답한다.

### 2.3 함정·체크리스트

- [ ] write-back에 **신뢰도·출처**를 남기지 않으면, 잘못 쓴 한 사실이 이후 모든 답을 오염시킨다.
- [ ] 중요한 갱신엔 **휴먼인더루프** 검수(4단계 원칙 재적용).
- [ ] 사실을 덮어쓰지 말 것 — 무효화로 과거를 보존.
- [ ] 모순 탐지 로직(같은 주어·관계의 상충 사실) 필수.

## 3. 에이전트 아키텍처 — 검색–추론–행동 루프

1. **검색(retrieve)**: 그래프 도구·GraphRAG·벡터로 관련 사실을 모은다.
2. **추론(reason)**: 모은 사실로 답을 만들거나 다음 행동을 정한다. 필요하면 질의를 재계획.
3. **행동(act)**: 사용자에게 답하고, 새 사실을 그래프에 **write-back**한다.

루프가 돌 때마다 그래프가 자라고, 자란 그래프가 다음 턴의 문맥이 된다.

**대표 응용**

| 응용 | 특징 |
| --- | --- |
| 개인 어시스턴트 | 대화가 쌓여 자라는 장기 기억 |
| 리서치 에이전트 | 도메인 KG 위를 걸으며 근거 추적·발견 기록 |
| 고객지원 에이전트 | 고객·이력·제품 그래프 읽기 + 상호작용 write-back |

**관통 과제 — 신뢰와 평가**: 에이전트가 그래프에 *쓰는* 순간 검증·휴먼인더루프가 결정적이 된다. 잘못 쓴 사실은 미래의 모든 답을 오염시킨다.

## 4. End-to-End 구축 파이프라인

```
비정형 코퍼스 ─▶ LLM 추출·검증(4) ─▶ 그래프 DB 적재(2) ─┬─▶ GraphRAG 인덱싱(5) ─┐
 문서·리포트·로그   스키마 유도        Neo4j·엔티티해소     └─▶ 임베딩·추론(6) ──────┤
                                                                                  ▼
                        ┌───────────────── 에이전트(7) ─────────────────┐   검색·추론·행동
   근거 있는 답변·행동 ◀─┤  질의: NL→Cypher   ·   write-back: 새 사실     ├─▶ 도메인 적용
                        └───────────────────────────────────────────────┘
```

### 4.1 ① 코퍼스 → 트리플 (4단계)

```python
from langchain_experimental.graph_transformers import LLMGraphTransformer

transformer = LLMGraphTransformer(
    llm=llm,
    allowed_nodes=["환자", "질환", "약물", "검사"],       # 도메인 스키마(예: 헬스케어)
    allowed_relationships=["진단", "처방", "부작용"],
    strict_mode=True,
)
graph_docs = transformer.convert_to_graph_documents(documents)
```

> **함정** — 청크 경계에서 사실이 잘리면 관계가 소실된다. 문맥을 넉넉히 청킹하고, 각 트리플에 **출처 근거**를 함께 뽑아 검증에 대비.

### 4.2 ② 트리플 → 그래프 DB (2단계)

```python
neo4j_graph.add_graph_documents(graph_docs)   # 엔티티 해소로 같은 개체는 병합

# 제약으로 무결성 확보(3단계 기본키)
# CREATE CONSTRAINT patient_id IF NOT EXISTS
# FOR (p:환자) REQUIRE p.id IS UNIQUE;
```

> **함정** — 엔티티 해소를 건너뛰면 같은 개체가 여러 노드로 쪼개져 다중 홉 질의가 끊긴다.

### 4.3 ③ 그래프 → 에이전트 도구 + write-back (5·6·7단계)

```python
tools = [
    graph_query,     # NL→Cypher 탐색 (7단계)
    graphrag_local,  # 개체 이웃 검색 (5단계)
    graphrag_global, # 커뮤니티 요약 종합 (5단계)
    predict_link,    # 링크 예측 (6단계)
]

def remember(fact: dict):
    """새로 확인된 사실을 유효 기간과 함께 write-back (7단계)."""
    neo4j.run(
        "MERGE (a {id:$s})-[r:REL {type:$t, valid_from:$now}]->(b {id:$o})",
        **fact,
    )

agent = build_agent(llm, tools=tools + [remember])
```

> **함정** — write-back에 신뢰도·출처를 남기지 않으면 오염이 전파된다. 중요한 갱신엔 휴먼인더루프.

**불변식**: 도메인이 바뀌어도 뼈대는 그대로. 갈아 끼우는 것은 두 칸뿐 — `allowed_nodes`/`allowed_relationships`(스키마)와 에이전트가 답하는 **질문**.

## 5. 도메인별 활용 사례 — 아키텍처 변주

| 도메인 | 스키마(노드·관계) | 대표 질문 / 에이전트 행동 | 무게중심 단계 |
| --- | --- | --- | --- |
| **헬스케어·바이오** | 약물·질환·유전자·논문 / 진단·처방·상호작용 | 약물 재창출 후보, 환자 360°, 근거 추적 리서치 | 6(링크예측)·4(검증) |
| **금융** | 계좌·거래·법인 / 이체·소유·지배 | 자금세탁 고리·위장 계좌, 리스크 전파, 제재 엔티티 해소 | 1(다중홉)·3(해소) |
| **사이버보안** | 자산·취약점·공격·행위자 / 노출·악용·연관 | 공격 경로 추론, 위협 인텔리전스, 침해 조사 | 6(경로)·7(에이전트) |
| **엔터프라이즈·고객지원** | 문서·티켓·제품·팀 / 참조·해결·소속 | 근거 있는 사내 Q&A, 온보딩·지원 | 5(GraphRAG)·7 |
| **추천·이커머스** | 사용자·상품·속성 / 구매·조회·유사 | 설명 가능한 추천, 함께 사는 상품 | 6(링크예측)·1 |
| **법률·컴플라이언스** | 계약·조항·판례·규정 / 인용·상충·적용 | 다중 홉 근거 추적, 컴플라이언스 점검 | 5·7·4(검증) |
| **개인·에이전트 메모리** | 사용자·선호·사건·사람 / 언급·선호·관계 | 시간에 걸쳐 자라는 장기 기억, "언제부터 바뀌었지?" | 7(temporal KG) |

### 5.1 무게중심 규칙 — 어느 단계에 힘을 싣는가

- **규제·안전이 본질**(금융·헬스케어) → 엔티티 해소·검증(3·4)의 무게가 크다. 잘못이 규제·안전으로 직결.
- **연결·종합이 본질**(엔터프라이즈 Q&A·법률) → GraphRAG(5)가 무게중심.
- **예측이 본질**(추천·신약) → 임베딩·추론(6)이 무게중심.
- **시간이 본질**(개인 메모리) → temporal KG(7)가 무게중심.

같은 뼈대 위에서 **어느 단계에 힘을 싣느냐가 도메인을 가른다.**

## 6. 프로덕션 체크리스트

"돌아가는 데모"와 "믿고 쓰는 시스템"을 가르는 벽.

| 관심사 | 리스크 | 대응 |
| --- | --- | --- |
| **확장성** | 커뮤니티 재계산·다중 홉 질의 비용 급증 | 인덱싱 주기, 질의 깊이 제한, 그래프 파티셔닝 |
| **최신성(freshness)** | GraphRAG 인덱싱은 무거움 | **증분 갱신**(바뀐 부분만), write-back과 결합 |
| **환각·정확성** | LLM 추출·text-to-Cypher가 틀림 | 출처 근거·스키마 검증·근거 경로 기본값 |
| **거버넌스·보안** | 접근 제어, 계보, 개인정보 | 노드·관계 단위 권한, 출처·계보 추적 |
| **평가** | 채점 기준 부재 → 개선 불가 | 근거 경로 정확성, 검색 재현율, write-back 신뢰도 |

- [ ] 증분 인덱싱 경로가 있는가(전체 재인덱싱에 의존하지 않는가).
- [ ] 모든 답이 근거 경로/출처를 동반하는가.
- [ ] write-back 사실에 신뢰도·출처·시간 메타데이터가 붙는가.
- [ ] 접근 제어가 노드·관계 수준에서 강제되는가.
- [ ] 자동 평가 하네스(근거 경로·재현율)가 있는가.

## 7. 커리큘럼 8단계 전체 지도

세 막 구조: **① 이해(1–3) → ② 지능(4–6) → ③ 에이전트(7–8).**

## 8. 핵심 원칙 요약 (에이전트 운영 지침)

- **주체 전환**: 사람이 짠 파이프라인이 아니라 에이전트가 그래프를 스스로 읽고 쓴다.
- **도구 규율**: text-to-Cypher·질의 계획은 강력하지만 스키마 검증·근거 경로 가드레일이 필수다.
- **기억 규율**: write-back은 사실을 덮어쓰지 않고 무효화로 축적한다(temporal). 오염 방지를 위해 신뢰도·출처·검수를 남긴다.
- **아키텍처는 하나, 변주는 도메인마다**: 코퍼스→추출→그래프→GraphRAG·추론→에이전트 write-back. 스키마와 질문만 갈아 끼운다.
- **힘점이 도메인을 가른다**: 규제→검증(3·4), 연결→GraphRAG(5), 예측→추론(6), 시간→temporal(7).
- **프로덕션은 체크리스트의 문제**: 확장성·최신성·환각·거버넌스·평가를 넘어야 데모가 시스템이 된다.
